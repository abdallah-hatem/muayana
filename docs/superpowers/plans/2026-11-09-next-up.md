### N1 — One-sheet capture (backend+frontend · logic)
Edge cases:
- [ ] Photo only → `new`, one history row (none→new) (§5.1)
- [ ] Photo + trade + description → `unassigned`, rows none→new, new→unassigned (§5.1, §6.7)
- [ ] + contractor of that trade → `assigned`, assignedAt set (§5.1, §4)
- [ ] Contractor lacking the trade → 409 WORKER_LACKS_CATEGORY, nothing created (§6.3)
- [ ] Inactive contractor / inactive trade → 409, nothing created (§6.11)
- [ ] Contractor without trade → 409 ISSUE_REQUIREMENTS, nothing created (§6.2, §4)
- [ ] Trade without description → stays `new` (no error) (§6.1, §5.1)
- [ ] Contractor + trade without description → 409 ISSUE_REQUIREMENTS, nothing created (§6.1)
- [ ] Archived site with fields → 409 ARCHIVED_SITE, nothing created (§6.11)
- [ ] Unauthenticated POST /issues with the new fields → 401 (§6.10)
- [ ] `assigned` on create writes exactly none→new and new→assigned (§6.7)
- [ ] Same client id twice with fields → one issue, same status (§6.9)
- [ ] Contractor picker lists only active contractors of the chosen trade; changing the trade clears a contractor who lacks it (§5.4, §6.3)
- [ ] Offline: sheet uses cached trades/contractors, item queued with fields (§5.2)
- [ ] Upload refused (409) → item failed with reason; "retry without contractor" uploads it as unassigned/new (§5.2)
- [ ] Sheet opens with keyboard down (no autofocus); add-photo-to-this-issue before save (spec F1)

### N3 — WhatsApp sends photo files (frontend · logic)
Edge cases:
- [ ] canShare({files}) → share called with photo Files and caption text containing no photo URLs (§5.5)
- [ ] canShare false → wa.me to the contractor's number with text + photo links (§5.5, §6.10)
- [ ] Share cancelled → no "Mark as sent?" prompt / no status change (§6.13)
- [ ] Batch with files → all photos of all `assigned` issues; too many/too large → split into several shares (§5.5)
- [ ] Photo fetch fails for one file → share the rest, caption notes the missing one (spec F3)
- [ ] Mark-as-sent flow unchanged after a successful share (§6.13)
- [ ] Re-sending an issue already `sent` or later → no prompt, status unchanged (§5.5)
- [ ] Batch over 200 assigned issues → shares + bulk calls in batches of ≤200 (§5.5)
- [ ] Batch fallback (no file sharing) → wa.me text with links (§5.5)

### N4 — Contractor Excel (shared+api+frontend · logic)
Edge cases:
- [ ] Column list is the same single shared definition used by the issues CSV (API refactored to it); CSV output unchanged (§7)
- [ ] Chosen columns only, in order; header language ar/en (§7)
- [ ] Default rows = contractor's `assigned` issues; every one, not a page (§5.5, §6.14)
- [ ] Photos embedded as images in their row (thumbnails ≤320px), not links; RTL sheet in ar (§7)
- [ ] Formula guard on text cells (§7)
- [ ] Share via canShare({files}) with .xlsx; fallback download (§5.5)
- [ ] After sharing, "Mark as sent?" yes → included `assigned` issues → sent in bulk (≤200 per call); no → unchanged (§5.5, §6.13)
- [ ] File > ~15 MB → warning, offer fewer issues (§5.5)
- [ ] Rows widened by the status filter → "Mark as sent" changes only the `assigned` ones (§5.5)
- [ ] Share cancelled → no prompt, no status change (§6.13)
- [ ] Bulk mark-as-sent where one issue breaks a rule → none change, error shown (§5.3)
- [ ] Photo-link columns are replaced by embedded pictures, never URLs in cells (§7)
