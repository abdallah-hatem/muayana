## Tasks

### T1 — Scaffold monorepo + design system (infra · surface) — deps: none
npm workspaces `apps/api` (NestJS + Prisma), `apps/web` (Next.js App Router + Tailwind v4 + shadcn/ui +
next-intl ar default/en, RTL), `packages/shared` (zod schemas + enums + types from the contract, built to dist).
Envelope interceptor + exception filter, ValidationPipe, config validation, `/api/v1/health`. Full Prisma schema
for every entity in §3 (User, Site, Category, Worker, WorkerCategory, Issue, Photo, StatusChange, per-site
number counter) + first migration. docker-compose Postgres. `scripts/db-agent.mjs` (template DB + per-agent DB),
e2e harness reading DB URL/ports from env. House lint + typecheck for every app. Playwright config (env ports,
`@smoke` tag, mobile + desktop projects). Design tokens from DESIGN.md in `globals.css` (light + dark, status
tokens, hazard stripe utility), Readex Pro + IBM Plex Mono via next/font, a dev-only `/design` preview page.
Root scripts: dev:api, dev:web, db:up, db:seed, db:agent, lint, typecheck, test, test:e2e, test:smoke.

### T2 — Auth, app shell, seed (backend+frontend · logic) — deps: T1
API: login (bcrypt, JWT 7d), me, patch me, change password, global JWT guard (public: login, health), login
rate limit. Web: login page, httpOnly cookie via route handlers, API proxy/fetch helper, middleware redirect,
app shell (bottom nav: Dashboard · Issues · **Capture shutter** · Inbox · Workers; top bar with site
switcher slot, language + theme toggle, settings), settings page (profile, language, password).
Seed: engineer from env (`SEED_ENGINEER_EMAIL/PASSWORD`), 12 categories, sample sites/workers/issues in every
status with placeholder photos when `SEED_ALLOW_SAMPLE=true`.
Edge cases:
- [ ] Wrong password → 401, same message as unknown email (§2: no account enumeration — checklist)
- [ ] Unknown email → 401
- [ ] 6th failed login within 15 min from same IP+email → 429 (§2 rate limit)
- [ ] Any data route without token → 401 (§6.10)
- [ ] Expired/garbage token → 401 (§6.10)
- [ ] Change password with wrong current → 400; new < 8 chars → 400 (contract)
- [ ] Locale other than ar/en → 400 (contract)
- [ ] Web: unauthenticated visit to /issues → redirect to /login (§6.10)

### T3 — Shared business rules, pure (shared · logic) — deps: T1
`packages/shared/src/rules/`: status requirements + `canMove(issue, to)`, automatic moves on patch
(`applyPatch`), `isOverdue(issue, todayCairo)`, phone normalise (EG local → +20), CSV cell escape + BOM writer,
WhatsApp message builder (ar/en), status order/labels keys. Used by API and web.
Edge cases:
- [ ] Move to unassigned without description → refused (§6.1)
- [ ] Move to assigned/sent/estimated/in_progress/solved without worker → refused (§6.2)
- [ ] Move to estimated without date → refused (§6.4)
- [ ] Any status → new → refused BACK_TO_NEW (§6.6)
- [ ] Skip forward assigned → in_progress with worker → allowed (§4)
- [ ] Back solved → sent → allowed (§4)
- [ ] Move to unassigned while worker set → refused (§4)
- [ ] Patch category to one the worker lacks → worker removed, status unassigned (§6.3)
- [ ] Patch worker on unassigned → assigned; patch worker null on sent → unassigned (§4)
- [ ] Patch estimatedDate on assigned/sent → estimated; on in_progress → stays (§4)
- [ ] Patch category + description on new → unassigned (§5.3); category only on new → stays new
- [ ] Overdue: date yesterday & open → true; today → false; solved/cancelled → false; no date → false (§4)
- [ ] Overdue uses Cairo date at 23:30 UTC boundary (§4 Cairo)
- [ ] Phone 01012345678 → +201012345678; +201012345678 stays; 00201… → +20…; letters → invalid (§3)
- [ ] CSV cell starting = + - @ → prefixed with '; quotes/commas/newlines escaped (§7)
- [ ] Cancelled requires category + description (§4)

### T6 — Issues API (backend · logic) — deps: T2, T3
Storage interface (`local` | `blob`), multipart upload, idempotent create, photos, list filters, patch with
automatic moves, status endpoint with history, bulk, merge, delete, per-site numbering in a transaction.
Edge cases:
- [ ] Create twice with same client id → one issue, second returns 200 same issue (§6.9)
- [ ] Create on archived site → 409 ARCHIVED_SITE (§6.11); unknown site → 404
- [ ] Create without photo → 400 (§6.5); non-image file → 400; >4MB → 413 (contract)
- [ ] Two concurrent creates on one site get different numbers; numbers never reused after delete (§6.12)
- [ ] capturedAt from client kept (§3)
- [ ] Add 11th before-photo → 409 PHOTO_LIMIT (§6.5)
- [ ] Delete last before-photo → 409 LAST_PHOTO (§6.5)
- [ ] Assign worker lacking the category → 409 WORKER_LACKS_CATEGORY (§6.3)
- [ ] Assign inactive worker → 409 INACTIVE_WORKER; choose inactive category → 409 (§6.11)
- [ ] Every status move writes exactly one history row; patch with no status change writes none (§6.7)
- [ ] Status to new → 409 BACK_TO_NEW (§6.6)
- [ ] Requirements unmet → 409 ISSUE_REQUIREMENTS (§6.1, §6.2, §6.4)
- [ ] assignedAt/sentAt/solvedAt set the first time only (§4)
- [ ] Reopen solved → assigned with worker, → unassigned without (§4)
- [ ] Bulk: one failing id → nothing changes, 409 lists it (contract all-or-nothing)
- [ ] Bulk >200 ids → 400 (contract)
- [ ] Merge: both must be new; photos moved; source deleted; >10 → 409 (§5.3)
- [ ] Delete non-new issue → 409 NOT_NEW (§3)
- [ ] List filters: each filter alone + combined; status list; overdue; q matches number/description/location (§5.8)
- [ ] limit 101 → 400; page beyond → empty (checklist)

### T10 — Capture + offline queue + PWA (frontend · logic) — deps: T2, T3
Camera capture page (file input `capture=environment`, multi-shot loop), client compression to ≤1600px JPEG,
IndexedDB queue with client UUIDs, auto-sync on online/open, retry/discard, failed after 5 tries, queue badge in
shell, "add to previous issue", PWA manifest + service worker for app shell.
Edge cases:
- [ ] Capture offline → item stored, badge count +1, nothing sent (§5.1)
- [ ] Reconnect → queue uploads in order; success removes item (§5.2)
- [ ] Upload succeeded but response lost → retry gets 200, item removed, no duplicate (§6.9)
- [ ] 5 failures → marked failed, kept (§5.2)
- [ ] Discard removes item and its blobs (§5.2)
- [ ] App reload with items queued → still there and resume (§5.1)
- [ ] Compression: 4000×3000 → long side 1600, JPEG (§3)
- [ ] Archived-site 409 → item marked failed with reason, not retried forever (§6.11)

### T11 — Sort inbox, issue page, status actions, WhatsApp send (frontend · ui) — deps: T2, T3
Inbox one-at-a-time sorter with big photo + category chips + description + worker picker (filtered by category),
bulk category, merge; issue detail page (gallery, edit, status stepper/stamp, history, estimate date, solve with
after photo, cancel, reopen); WhatsApp send (Web Share with files, wa.me fallback, "Mark as sent?" sheet); batch
send from worker page (component exported for T9 to mount — T9 mounts it after merge).
Interaction cases: save without description → inline error · worker picker shows only matching active workers ·
invalid move button disabled with reason · share cancelled → no status change · double tap on status → one change.

### T12 — Issues list, filters, export, dashboard (frontend · ui) — deps: T2
Issues list with URL-synced filters (bottom sheet on mobile), sort, infinite scroll, overdue badge; export dialog
(choose columns, issues/history); dashboard (counts, bars by category/worker/site, each linking to filtered list).
Interaction cases: filters survive reload (URL) · export uses current filter · empty filter result state · clear all.
