# T6 — Issues API

Branch `feature/t6-issues-api` (from `dev`). One commit (this report included). Not pushed, not merged.
No schema change (the T1 schema already had `Site.nextNumber`, every index the filters need, and the
history table).

## Built
- **Module** `apps/api/src/domains/issues`: controller → `IssuesService` → `IssueRepository` (issues,
  photos, history; row locks via `SELECT … FOR UPDATE` in id order) + `IssueRefsRepository` (read-only
  facts about sites/categories/workers — no sites/categories/workers module created).
- **Routes** (contract "Issues"): `POST /issues` (multipart, 201 / 200 for an existing client id, also
  when two identical uploads race), `POST /issues/:id/photos`, `DELETE /issues/:id/photos/:photoId`,
  `GET /issues` (every IssueFilter field, 4 sorts, limit cap 100), `GET /issues/:id` (+ history),
  `PATCH /issues/:id`, `POST /issues/:id/status`, `POST /issues/bulk`, `POST /issues/:id/merge`,
  `DELETE /issues/:id`.
- **Rules** only from `@muayana/shared`: `applyPatch` (PATCH, bulk category/worker), `canMove` +
  `reopenTarget` (via `issues.pure.ts` `planMove`/`resolveTarget`), `FIRST_REACHED_FIELD`
  (`firstReachedStamp`), `isOverdue` (response), `CLOSED_STATUSES` (overdue query).
- **Numbering**: `UPDATE sites SET next_number = next_number + 1 … RETURNING` inside the create
  transaction — concurrent creates serialise on the site row; numbers never reused.
- **Storage** `apps/api/src/common/storage/`: `PhotoStorage` interface (`PHOTO_STORAGE` token, global
  `StorageModule`), `LocalPhotoStorage` (UPLOAD_DIR, `${PUBLIC_UPLOAD_BASE_URL}/<key>`, refuses `../`
  keys), `BlobPhotoStorage` (`@vercel/blob` `put`, public, random suffix; key = pathname). Added dep
  `@vercel/blob`.
- **Images** `common/utils/image.util.ts`: `sniffImageType` (jpeg/png/webp magic bytes), `toStoredImage`
  (sharp: EXIF rotate, long side ≤ 1600, JPEG → width/height). >4 MB → 413 (multer limit).
- **Shared for T7**: `apps/api/src/common/utils/issue-filter.util.ts` — `buildIssueWhere(filter, now)`,
  `issueOrderBy(sort)`, `overdueWhere/notOverdueWhere(now)`, `cairoDayStart`, `dateOnlyToDb/dbToDateOnly`.
  DTO `IssueFilterDto` / mixin `WithIssueFilter(Base)` in `domains/issues/dto/issue-filter.dto.ts`.
- `common/interceptors/with-status.interceptor.ts`: `WithStatus(status, body)` for a runtime status
  (idempotent create) without touching `res` in a controller.

## Decisions (no business § change needed)
- Creating an issue writes a history row `null → new` (as the seed does); "every move writes one row"
  counts moves after that. Merge deletes the source with its creation row; the target gets none.
- Asking for the current status (status endpoint, bulk) is a no-op: 200, no history row (double tap).
- Reopen: from `solved`/`cancelled`, a request for `assigned` or `unassigned` lands on `reopenTarget`.
- Bulk: unknown ids → 404 `data.ids`; rule refusals → 409 with the first code, `data.ids` +
  `data.failures[{id, code, missing}]`; nothing written. Empty change → 400.
- Rule 409s carry `data.missing` (requirements) for the web to show what is missing.
- PATCH accepts `categoryId: null` (shared `UpdateIssueRequestSchema` doesn't) so the rule answers 409.
- Uploads are re-encoded to JPEG server-side (keys end in `.jpg`; PNG/WebP accepted).
