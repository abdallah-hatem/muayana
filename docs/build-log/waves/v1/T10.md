# T10 — Capture + offline queue + PWA

Branch `feature/t10-capture-offline` (from `dev`). One commit (this report included). Not pushed, not merged.

## Built
- **`/capture`** (`app/(app)/capture/`): `CaptureScreen` — dark camera view (the `dark` token scope on the
  section, full-bleed to the edges of `main`; checked at 375px, RTL, with a real 4000×3000 shot), site chip + "N waiting to upload" chip on top, last shot
  full-bleed with the shutter flash, bottom panel: location (optional), "Add a note" → 3-row textarea, last
  shot thumbnail · big shutter · "To previous". `CameraInput` (`components/ui/camera-input.tsx`, hidden
  `<input type=file accept=image/* capture=environment>`, value cleared after each pick so the loop is
  shutter → camera → shutter). Shots are chained so "add to previous" always sees the issue before it.
  `takeShot()` (`capture-shot.ts`): compress → enqueue → `syncQueue()`. `SitePicker` (bottom drawer, active
  sites, skeleton while loading, empty + offline + failed states). `useCaptureSites()` — `GET
  /sites?archived=false&limit=100`, last used site preselected (localStorage), the list cached on the phone
  for offline capture, a stored site that is no longer active is dropped. `useLastIssue()` — the issue "add
  to previous" joins, kept in localStorage (`useSyncExternalStore`, no hydration flash); only enabled when it
  belongs to the chosen site.
- **Compression** `lib/compress-photo.ts`: `createImageBitmap(file, { imageOrientation: 'from-image' })`
  (EXIF orientation baked into the pixels) → canvas → JPEG 0.82, long side ≤ `PHOTO_MAX_DIMENSION`;
  `fitWithin()`; an undecodable file the API accepts (jpeg/png/webp ≤ 4 MB) goes up as is, anything else →
  `PhotoUnreadableError`.
- **Queue** `lib/offline-queue/` (`idb`): store `muayana-capture/queue`, items `{ id (uuid v4 from the
  phone, = issue id for create), kind create|addPhoto, issueId, siteId, capturedAt, note, location, photo
  {bytes, type}, attempts, status pending|failed, lastError, seq, nextAttemptAt }`. `enqueue`, `listItems`,
  `discardItem` (a discarded create also drops the photos queued for it), `retryItem` (attempts reset →
  sync), `onQueueChange`, `useQueueItems`/`useQueueCount`. Sync (`sync.ts`): single-flight with one queued
  re-run; oldest first; skipped entirely while `navigator.onLine` is false (offline time never burns
  attempts); 200/201 → removed; network / 408 / 429 / 5xx → attempts+1, backoff 5 s·2ⁿ (cap 5 min) and the
  run stops to keep order; 5th failure → failed, kept; other 4xx (409 ARCHIVED_SITE, 404, 413, 400) →
  failed at once with the code, never retried automatically; 401 stops the run (client goes to login).
  `startQueueSync()` — runs on app open, on `online`, and when a backoff ends; captures call `syncQueue()`.
- **Shell**: `QueueSheetProvider` + `QueueSync` in `AppShell`; `QueueChip` in the top bar (hidden on
  /capture, which shows its own; red when an item failed); count badge on the bottom-nav shutter;
  `QueueSheet` (drawer: thumbnail from the queued bytes, kind, time, location, status + tries, translated
  reason, Retry, Discard with an inline confirm, offline banner).
- **`useOnline()` / `useNeedsConnection(onBlocked)`** (`lib/use-online.ts`) — for T11/T12: `guard(action)`
  runs the action online, offline calls `onBlocked` and sends nothing; message key
  `capture.needsConnection`.
- **PWA**: `app/manifest.ts` (name/short_name معاينة, ar/rtl, standalone, theme `#fad117` = `--primary`,
  background = light `--background`; hex conversions noted in the file), icons in `public/icons` (192, 512,
  maskable 512, apple-touch 180) from `scripts/make-icons.mjs` (yellow square, ink "م", centred on its ink
  box). Root layout: `themeColor` light/dark, icons. `public/sw.js`: precaches /capture + the static
  chunks its HTML names, pages network-first with the cached /capture as the offline fallback,
  `/_next/static` cache-first, never `/api/*`, never RSC payloads, never a redirected (signed-out)
  response. Registered by `QueueSync` in production only; the page posts its loaded chunk URLs to it.
- i18n namespace `capture` (ar + en), registered.

## Deviations / notes for the plan
- The photo is stored as `{ bytes: ArrayBuffer, type }`, not a `Blob`: Safari has refused Blobs in
  IndexedDB and ArrayBuffers clone everywhere (including fake-indexeddb).
- Items carry `issueId` besides `id` (for addPhoto the target issue), plus `seq` and `nextAttemptAt`.
- "Add to previous" photos go up as `kind=before`.
- `useOnline` treats the server render as online. The capture screen is always the dark camera look
  (mockup), in both themes.
- Found and fixed while testing: a sync request arriving while the previous run was finishing was lost
  (the run is now cleared in the same tick as its last re-run check).
- Business docs unchanged (behaviour matches §5.1–5.2, inv. 9, 11).
