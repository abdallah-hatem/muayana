# D1 + D2 — Delete an issue / a contractor completely

Branch `feat/permanent-delete`, commit `95e0c6e`. Class: logic (backend + frontend). Spec
`docs/specs/2026-11-09-permanent-delete.md`.

## Built
- **Schema**: `Issue.formerWorkerName` (nullable, `former_worker_name`), migration `20261109140131_issue_former_worker_name`
  (created with `--create-only` on the agent DB, then `migrate deploy`).
- **Shared**: `DomainErrorCode.WORKER_HAS_ISSUES`; `WorkerIssuesChoiceSchema`, `DeleteWorkerQuerySchema`,
  `WorkerIssuesSummarySchema` (+ types); `Issue.formerWorkerName`; `IssueState.formerWorkerName?`.
  The §6.2 exception lives in `rules/status.ts#keepsFormerWorker`, read by `missingFor` (so `canMove`) and `applyPatch` —
  a `solved` issue with only the former name stays valid while it stays solved; any other move needs a real worker,
  reopen lands on `unassigned` (`reopenTarget` unchanged). Exports: `exportWorkerName` → `Name (deleted)` / `Name (محذوف)`.
- **API**: `DELETE /issues/:id` any status (NOT_NEW refusal removed; merge still uses NOT_NEW). `DELETE /workers/:id?issues=keep|delete`
  (`DeleteWorkerQueryDto`): locks the worker row, counts his issues/photos, 409 with the counts when he has issues and no
  choice; `keep` → open issues `unassigned` + estimate cleared + one history row each (bilingual note naming him), closed ones
  lose the worker and get `formerWorkerName`; `delete` → his issues (photos/history cascade). All on `tx`, sequential queries
  (1-connection pool). Photo files go after commit through the new shared `common/storage/discard-photos.ts`
  (issues service switched to it). Choosing a contractor again clears `formerWorkerName`.
- **Web**: `issues/[id]/delete-issue.tsx` (ConfirmSheet + usePendingAction; every status; number + photo count; toast;
  back to `/issues`, `/inbox` for a `new` one). Issue page shows a deleted contractor as "Name (deleted)" with a hint.
  `workers/[id]/delete-worker-sheet.tsx`: plain confirm without issues; with issues the counts and two choices — keep, or the red
  "delete his N issues and M photos too" with a second confirm (Back / Delete permanently). Counts come from the loaded issues;
  a 409 from the plain confirm swaps in the API's counts. Delete is disabled until his issues load. `deleteWorker(id, issues?)`.
  Copy in ar + en (`issue.delete`, `issue.former`, `workers.delete`, `workers.toast`), Arabic plurals one/two/few/many.
- **Contract** updated (both DELETE rows, `formerWorkerName`, `WORKER_HAS_ISSUES`).

## Notes / decisions
- Business doc unchanged: behaviour matches §3/§6. Two details it doesn't spell out: the kept name stays on an issue
  reopened to `unassigned` and is cleared when a new contractor is chosen; the keep-history note is bilingual.
- The issue list rows show no contractor at all, so the former name appears on the issue page, the CSV and the Excel only.
- The old "Deactivate instead" path in the contractor delete sheet is gone (Deactivate stays on the page).
