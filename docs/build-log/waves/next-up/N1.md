# N1 — One-sheet capture

Branch `feat/n1-capture-sheet`, commit `59037e5`. Class: logic (backend + frontend).

## Built
- **Shared** `packages/shared/src/rules/patch.ts`: `CAPTURED_STATE` + `planCapture(fields, ctx)` — `applyPatch` on a fresh
  `new` issue. The API (create) and the web (sheet pre-check) both call it; no rule is re-stated.
  `CreateIssueRequestSchema` gains `categoryId?`, `workerId?`, `priority?`.
- **API** `issues.service.ts#create`: trade checked choosable (§6.11), contractor facts read, `planCapture` decides the
  landing status; checked before the photo is stored and again inside the create transaction. Writes `none → new` and
  one row for the landing move; `assignedAt` via `firstReachedStamp`. Refusals create nothing. Idempotent repeat unchanged.
  DTO + repository `createIssue` take the fields. Contract doc `POST /issues` row updated.
- **Web** `app/(app)/capture/capture-sheet.tsx`: one bottom sheet after the photo(s) — thumbnails + "add another photo",
  place, description, trade chips, contractor (`WorkerSelect` over the active contractors of the trade, with open counts;
  a trade change drops a contractor who lacks it), priority; Save / Photo only (closing = photo only). Opens with focus on
  the sheet (`BottomSheet keepKeyboardDown`). A blocked save (contractor without description) focuses the description.
- **Queue**: the sheet's photos are stored at once as `draft` items (nothing lost if the app closes; drafts left over are
  promoted to photo-only uploads when the sync starts); Save commits them with the fields (`commitDraft`). Items carry
  `categoryId/workerId/priority`; the upload sends them. A failed new issue refused for its contractor
  (WORKER_LACKS_CATEGORY / INACTIVE_WORKER / INACTIVE_CATEGORY / ISSUE_REQUIREMENTS) shows "Retry without the worker":
  same client id, no `workerId` (and no trade when the trade was the refusal).
- **Offline lists**: `useCaptureLookups` fetches active categories + workers, caches them in `capturePrefs`
  (validated with the shared zod schemas, slimmed), and falls back to the cache offline/unreachable; the sheet shows
  "may be out of date" when the lists are cached or the phone is offline.
- **Extracted**: `WorkerSelect` + `WorkerNeedsCategory` from `components/worker-picker.tsx` (WorkerPicker now uses them);
  `listActiveWorkers` endpoint.
