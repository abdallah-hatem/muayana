# N3 — WhatsApp sends the photo files

Branch `feat/n3-whatsapp-photos`, commit `f63948b`. Class: logic (frontend + shared builder).

## Built
- `packages/shared/src/rules/whatsapp.ts`: options `withPhotoLinks` (false → caption without photo links),
  `part` (`(1/3)` first line, only when there are ≥2 parts), `missingPhotos` (closing line naming the issue
  numbers, deduped), batch `total` (greeting counts the whole batch when a share carries part of it).
- `apps/web/src/lib/whatsapp-share.ts`: `loadIssuePhotos` (allSettled; `#14-1.jpg`, `image/jpeg`; failed ones
  dropped and flagged), `fitsOneShare` (≤10 files, ≤50 MB — Chromium's limits — and `canShare`), `planShares`
  (whole issues packed in order; an issue too big alone is halved), `shareInParts` (first share on the tap,
  each next one on its own tap via `ShareMore`; a non-Abort share error on >1 file halves that share and
  retries on the next tap; AbortError → `cancelled`; no file sharing / no file at all → wa.me with links).
  Replaced `loadPhotoFiles`/`shareToWhatsApp` (only callers were the send components).
- `components/send/send-flow.tsx`: while parts remain the button reads "Share part 2 of 3" with a hint
  ("pick the same chat each time"); "Mark as sent?" only after the last part; cancel at any part resets.
- `send-to-worker.tsx`: one `usePhotoFiles` hook prefetches before-photos for the issue / the current batch
  (keeps the tap's user activation). Batch keeps ≤200 per batch and one bulk call per batch.
- i18n `send.parts.{next,hint}` (ar/en).

## Edge cases ↔ tests (`apps/web/src/components/send/send-photos.test.tsx`)
- canShare({files}) → share called with photo Files and caption text containing no photo URLs (§5.5)
- canShare false → wa.me to the contractor's number with text + photo links (§5.5, §6.10)
- Share cancelled → no "Mark as sent?" prompt / no status change (§6.13) — single; plus "… — batch, mid-way"
- Batch with files → all photos of all `assigned` issues; too many/too large → split into several shares (§5.5)
  (+ "Batch share refused for size → split in two, the rest shared on the next taps (§5.5)")
- Photo fetch fails for one file → share the rest, caption notes the missing one (spec F3)
- Mark-as-sent flow unchanged after a successful share (§6.13)
- Re-sending an issue already `sent` or later → no prompt, status unchanged (§5.5)
- Batch over 200 assigned issues → shares + bulk calls in batches of ≤200 (§5.5) (230 issues: 20+3 shares, bulk 200+30)
- Batch fallback (no file sharing) → wa.me text with links (§5.5)
- Also: `lib/whatsapp-share.test.ts` (planShares packing / one-issue split), shared builder tests (no links;
  `(1/3)` + missing line), new `@smoke` "send on WhatsApp — the photo goes as a file, caption without links"
  in `e2e/sort-issue-send.spec.ts` (real API photo fetched → `#N-1.jpg`).

## Notes / plan corrections
- Sequential shares need a tap each (Web Share requires fresh user activation) — hence the "Share part k of n" button.
- Batch prefetches every photo of the current batch (≤200 issues) into memory on the contractor page when the
  browser can share files; fine for compressed photos, worth watching on low-end phones.
- Local smoke: the API must run with `PUBLIC_UPLOAD_BASE_URL=http://localhost:<api port>/uploads` and
  `CORS_ORIGINS=<web origin>`, else photo URLs point at the main checkout's API.
- Business docs unchanged (behavior matches §5.5).
