## Deviations / notes
- The contractor page has no status filter; the **status choice lives in the Excel sheet** (chips, default `assigned`,
  counts from the worker). Same rule as the brief, no page edit beyond the mount line.
- More than 200 `assigned` issues: each bulk call is all-or-nothing on the server (§5.3); a refusal of a later call
  can't undo an earlier one. Rule breaks known on the phone (`canMove`) are refused before any call; a later-call
  refusal says how many were already marked. Making it all-or-nothing across calls would need an API change.
- `lastNote` / `daysOpen` of closed issues read each issue's detail (history) — only when those columns are chosen.
- A thumbnail that can't be read leaves its cell empty (the file is still built).
- `lib/share-file.ts` repeats the 5-line AbortError check of `lib/whatsapp-share.ts` — left unshared to stay out of
  N3's file; fold together after N3 merges.
- The guarded phone cell shows as `'+20…` in the Excel, as it already does in the CSV (§7 rule).
- No business § change: behaviour matches §5.5 / §7 as written.
