# Muayana (معاينة) — site audit & snag tracker — spec

Date: 2026-11-05 · Run mode: fully autonomous · Status: approved (autonomous, against the goal)

## Goal (user's words, condensed)
A mobile-first web app, like Prime Property, for an audit engineer who inspects buildings. He photographs
everything wrong (a broken brick, a cracked wall, a dirty surface…), later sorts each photo under a trade
category (نقاشة، كهرباء، سباكة، محارة…), and assigns it to a worker of that trade. Workers have no
accounts; the engineer enters them and their categories (one or more). The engineer moves every issue
through statuses himself (unassigned, assigned, sent to the worker e.g. on WhatsApp, estimate received,
in progress, solved…). He can see every worker with their details and issues, and export CSV for any
filter with any details.

## Users and roles
- **Engineer** — the only user. Signs in with email + password. Does everything.
- **Worker** — not a user. A record the engineer keeps; reached outside the app (WhatsApp / phone).

## Entities
- **Site** — name, address (optional), notes, archived flag.
- **Category** — trade; name (ar), name (en), colour, sort order, active flag. Seeded with the common trades.
- **Worker** — name, phone (WhatsApp), categories (≥1), notes, active flag.
- **Issue** — site, photos (1–10, "before"), optional "after" photos, description, location text,
  category (empty until sorted), worker, priority, status, estimated completion date, status history.
- **Status change** — issue, from, to, when, optional note. Append-only.

## Statuses (engineer-controlled)
`new` (captured, not sorted) → `unassigned` → `assigned` → `sent` → `estimated` → `in_progress` → `solved`
plus `cancelled` (not a real issue / duplicate). Rules in the business doc §4.

## Flows
1. **Capture** (on site, fast): pick site → camera → take photo → optional quick note/location → next.
   Each photo becomes an issue in `new`. Works offline; queue badge shows pending uploads.
2. **Sort** (after the walk): an inbox of `new` issues, one at a time, big photo; tap a category chip,
   fill description/location/priority, optionally pick a worker → next. Bulk select + set category too.
   Merge: add more photos to an issue; combine two captures of the same defect.
3. **Assign**: worker picker shows only active workers of the issue's category.
4. **Send**: "Send on WhatsApp" — shares the photo(s) + a prefilled Arabic message via the phone's share
   sheet (Web Share with files), falling back to a `wa.me` link with photo links. Then the app asks
   "Mark as sent?". Batch: send all of a worker's assigned issues in one message.
5. **Track**: set estimate date → `estimated`; `in_progress`; `solved` (optional after-photo, note).
   Overdue = estimate date passed and not solved/cancelled.
6. **Workers**: list with counts by status; detail page with contact buttons (call / WhatsApp), categories,
   and their issues grouped by status.
7. **Dashboard**: counts by status, unsorted inbox count, overdue, by category, by worker, per site.
8. **Export CSV**: from the issues list with its current filters, choosing columns; workers export with
   counts. UTF-8 with BOM so Excel shows Arabic.

## Out of scope (v1)
Worker accounts or worker portal; multiple engineers; PDF reports; client/owner sharing links;
in-app messaging; automatic WhatsApp sending (WhatsApp Business API); floor-plan pinning; native app.
